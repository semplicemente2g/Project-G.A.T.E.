# Project G.A.T.E. (Guardrail Agent Testing & Evaluation)
## An LLM-as-a-Judge Architecture for Safety and Observability in Intelligent Agents.
[🇮🇹 **Leggi in Italiano**](README.md)

Experimental architecture that implements an advanced multi-agent workflow based on the **Google Agent Development Kit (ADK)**. The main goal is to run a "Cognitive Stress Test" on Large Language Models (LLMs), evaluating their ability to maintain context, comply with complex (even contradictory) business rules, and resist prompt injection attacks or mid-conversation role changes.

## Workflow Architecture

The workflow (`StressTest_Parallel_Pipeline_v5`) is orchestrated through a graph of custom agents and nodes in Python:

1. **Memory Management (Custom Node & LlmAgent):**
   - Intelligently extracts the conversation history.
   - Intercepts secret system directives ("MODIFICA ISTRUZIONE:") diverting execution through conditional routing (Bypass).
   - Uses a `Memory_Summarizer_Agent` (based on Gemini 3.1 Flash-Lite) to condense the history and extract rules and policies in a structured way.

2. **Main Agent:**
   - Receives the "clean" and compressed prompt.
   - Is tasked with responding to the user (in this case with complex roleplay rules, e.g. playing a Lead Developer for "Nexus Cybernetics" while respecting specific company policies and maintaining consistency regarding the user's name).

3. **Parallel Evaluation (LLM-as-a-Judge):**
   - The main agent's response is submitted to the simultaneous and parallel judgment of 3 different LLMs to mitigate evaluation bias:
     - **Judge 1:** Gemini 2.5 Flash
     - **Judge 2:** OpenAI GPT OSS 120B model (via Groq inference)
     - **Judge 3:** Qwen 3.6 27B (via Groq inference)
   - The judges return a *score* (from 1 to 10) and a comment evaluating context retention and the logic of the response.

4. **Synthesis (Merger Agent):**
   - A `Merger_Analysis_Agent` analyzes the JSON produced by the judges, calculates the average score, and produces a "Cognitive Stress Test Report" in Markdown format.

5. **Observability and Telemetry:**
   - The scores generated by the judges are extracted and sent to **LangSmith** via a custom node (`Send_To_LangSmith`) as *formatted feedback*, ensuring traceability of performance during the stress test.

## File Structure

- `agent.py`: The core file containing the ADK architecture definition, system prompts, agent configuration, and workflow nodes.
- `conversazione_stress_test.md`: A predefined 6-turn script. It consists of an intensive roleplay test (Nexus Cybernetics) full of pitfalls, emergency clauses, union directives, and latent instructions used to challenge the workflow's cognitive resilience.
- `.env`: (To be configured) File containing the API keys for Google, Groq, Anthropic, OpenAI, and the LangSmith endpoint configuration.

## Prerequisites

Make sure you have Python 3 installed and configure the following environment variables in your `.env` file:

```env
GOOGLE_API_KEY="Your_GOOGLE_API_KEY"
OPENAI_API_KEY="Your_OPENAI_API_KEY"
GROQ_API_KEY="Your_GROQ_API_KEY"

# LangSmith Configuration
LANGCHAIN_TRACING_V2="true"
LANGCHAIN_ENDPOINT="https://api.smith.langchain.com"
LANGCHAIN_API_KEY="your_api_key"
```

Also install the dependencies required for the project (e.g. `google-adk`, `langsmith`, `python-dotenv`).

## How to Run the Project

The workflow is designed to be interfaced with the Google ADK execution UI. The final exported variable is `root_agent = pipeline`, ready to be imported and invoked in the runtime. Use the turns defined in `conversazione_stress_test.md` to feed the chat and explore how the system dynamically evaluates context degradation or resilience under stress.
